01 / BEFORE YOU START

실습 환경 준비

설치와 가입을 마쳤다면 아래 방법으로 확인해 보세요.

⌘STEP 01

Git 설치

운영체제에 맞는 Git을 설치한 뒤 터미널에서 버전을 확인합니다.

git --version
공식 설치 페이지 ↗이 항목은 제출한 출력 형식을 확인합니다. 실제 설치 여부를 브라우저에서 직접 검증할 수는 없습니다.
◎STEP 02

GitHub 가입

계정을 만들고 이메일 인증을 완료하세요. 공개 프로필을 조회해 계정 존재 여부를 확인합니다.

github.com/signup
GitHub 가입하기 ↗이메일 인증과 계정 소유 여부는 공개 API만으로 확인할 수 없습니다.

실습 과제

01

공개 저장소 만들기

본인 계정에 공개 저장소를 직접 만드세요. 남의 저장소를 Fork한 것은 인정하지 않습니다.

git init → git remote add origin → git push
15점
02

README 작성하기

README.md에 학습 목표를 적고, git-lab-사용자이름 문구를 넣으세요.

git add README.md
15점
03

커밋 두 번 만들기

기본 브랜치에서 서로 다른 변경을 두 번 커밋하고 터미널에서 push하세요. GitHub 웹 편집기로 만든 커밋은 인정하지 않습니다.

git commit -m "docs: add learning goal"
15점
04

새 브랜치 푸시하기

practice/feature 브랜치를 만들고 파일을 수정해 커밋한 뒤 푸시하세요. 기본 브랜치와 내용이 같으면 통과하지 않습니다.

git switch -c practice/feature
15점
05

이슈 열기

저장소에 학습 계획이라는 문구가 들어간 이슈를 본인 계정으로 만드세요.

GitHub → Issues → New issue
10점
06

Pull Request 만들기

practice/feature에서 기본 브랜치로 PR을 본인 계정으로 만드세요. 브랜치에 새 변경 사항을 커밋해야 PR을 만들 수 있습니다.

GitHub → Pull requests → New pull request
10점
✦

권장 순서: README와 커밋 2개를 기본 브랜치에 푸시 → 새 브랜치에서 파일 수정 및 커밋 → 푸시 → PR 생성. PR은 열려 있거나 병합된 상태 모두 인정합니다. 이 과정은 터미널에서 Git을 직접 쓰는 것이 목표이므로, GitHub 웹 편집기로만 만든 커밋은 채점되지 않습니다. 웹으로 만든 커밋은 커밋 정보의 committer가 GitHub로 기록되어 구분됩니다.

점수와 순위는 어떻게 정하나요?

브라우저 점수나 JSON 파일을 그대로 받지 않고 서버가 본인 소유 공개 저장소를 재검사합니다. 초급은 서버에서 확인할 수 없는 Git 설치 출력 10점을 제외한 90점, 실전은 325점 만점입니다. 확인 불가 항목이 있으면 기존 기록을 유지합니다. 예제·공식 정답 저장소는 등록할 수 없습니다.

동점은 공동 순위(1위, 1위, 3위)이며 표시 순서는 먼저 달성한 기록이 앞섭니다. 같은 사용자가 재제출하면 더 높은 점수만 반영됩니다. 저장소의 제출 당시 상태를 평가하므로 이후 변경 사항은 재제출해야 합니다. 자신의 PC에서 실제 명령을 입력했는지까지 증명하는 시험 인증 수단은 아닙니다.

채점 실패 시 GitHub Actions 실행 기록의 원인을 해결한 뒤 제출 이슈 본문을 수정하거나 닫았다가 다시 열면 재검사합니다.
