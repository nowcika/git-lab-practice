3. 테스트 중 확인된 "실제로 안 되는 것"
================================================================================

3-1. [치명] macOS 기본 Git 출력이 채점에서 실패
     app.js:74 정규식에 실제 출력 문자열을 넣어 확인한 결과:
       "git version 2.48.1"                 -> 통과
       "git version 2.43.0"                 -> 통과
       "git version 2.45.1.windows.1"       -> 통과
       "git version 2.39.5 (Apple Git-154)" -> 실패  ← macOS 기본 설치
     guides.js가 macOS에 xcode-select 설치를 안내하므로,
     안내대로 한 macOS 학습자는 이 항목에서 항상 0점입니다.

3-2. [치명] 미인증 GitHub API 한도를 초과함
     실측한 요청 수:
       시나리오 채점 1회 = api() 15회 + scenarioContent() 20회 = 35회
                          (+ GitHub Pages 본문 fetch 1회)
       초급 채점 1회     = 7회
     이 PC에서 확인한 미인증 한도: core limit 60회/시간(IP 기준).
     -> 한 사람이 두 번만 채점해도 한도에 근접하고, 같은 시간대 재시도는 403.
     -> 공용 IP를 쓰는 교육장에서는 사실상 몇 명만 채점하면 전원이
        "확인 불가"만 보게 됩니다.

3-3. [치명] 정답 저장소 주소만 넣으면 290점
     scenarios.js:259가 nowcika/git-scenario-solution 을 Fork 검사에서 예외 처리.
     이 주소는 페이지의 "전체 정답 저장소 ↗" 버튼에 그대로 노출돼 있습니다.

3-4. [치명] Git을 쓰지 않고도 시나리오 점수 획득 가능
     검증 방법: git merge/rebase/cherry-pick/reflog를 전혀 쓰지 않고,
     페이지에 적힌 정답 문구만 텍스트 파일로 만들어 커밋한 임시 저장소를 채점.
     결과: scenarios · local-only · 75/290점
           [pass] upstream 변경 15점
           [pass] 복구 결과(reflog) 15점
           [pass] diff 보고서 15점
           [pass] show 보고서 15점
           [pass] blame 보고서 15점
     웹 채점도 동일 기준이므로 같은 결과가 나옵니다.

3-5. [중요] Playwright 설정이 GitHub 토큰을 외부 도메인에도 전송
     playwright.config.js가 use.extraHTTPHeaders에 Authorization을 넣는데,
     이는 브라우저의 모든 요청에 적용됩니다.
     styles.css:1이 fonts.googleapis.com을 @import 하므로 UI 테스트 중
     Google 도메인으로도 토큰이 전송됩니다.

3-6. [중요] 새로 clone하면 로컬 검증기가 동작하지 않음
     bin/, lib/, LOCAL-GRADER.md, tests/local-grader.test.cjs,
     tests/basic-ui.spec.js 가 커밋되지 않았고 origin/main에도 없습니다.
     -> 원격에서 clone한 사람은 `npm run grade:local`, `npm run test:local`
        실행 불가. `npm test`는 첫 단계에서 실패.
     참고: 원격 package.json에는 test:local / grade:local 스크립트 자체가
     아직 없습니다(로컬 package.json만 수정된 상태).

3-7. [중요] 문서대로 설치하면 npm test가 브라우저를 못 찾음
     DESKTOP-HANDOFF.md: `npx playwright install chromium`
       -> ~/.cache/ms-playwright/chromium-1243/... 에 설치
     package.json scripts: PLAYWRIGHT_BROWSERS_PATH=0
       -> node_modules/playwright-core/.local-browsers/chromium-1243/... 를 탐색
     두 경로가 다름을 직접 확인했습니다. 새 PC에서는 UI 테스트가 실패합니다.
     (test:scenario는 브라우저를 띄우지 않아 영향 없음)

3-8. [보통] --offline은 항상 종료 코드 2
     오프라인에서는 4개 항목이 항상 "확인 불가"이므로 전부 통과해도 2입니다.
     자동화(CI, 채점 스크립트)에서 성공/실패를 구분할 수 없습니다.

3-9. [보통] --repo를 빼면 현재 폴더를 조용히 채점
     인자 없이 `node bin/grade-local.js`를 실행하면 이 프로젝트 저장소 자체가
     제출물로 채점되어 "50/100점"이 출력됩니다. 경고가 없습니다.

3-10. [보통] 실패 사유 안내가 일반 문구뿐인 항목이 있음
     온라인 채점 실행 결과 중:
       [fail] 학습 계획 이슈: 0/10 — 조건 미충족: 파일·이력·소유자·push 상태의 근거를 확인하세요.
       [fail] 해당 저장소의 feature PR: 0/10 — (같은 문구)
     어떤 조건이 어긋났는지 알 수 없습니다.

4. 문제 없이 동작하는 것으로 확인된 부분
================================================================================
  - 초급 100점 / 시나리오 290점 배점 합계와 화면 표기가 정확히 일치
  - 18개 시나리오 정의와 채점 task 수(1+17) 일치
  - 로컬 검증기의 revert 진위 검사(patch-id 대조), merge 부모 검사,
    빈 커밋 차단, shallow clone 보류, 태그 객체 추적 등은 실제로 동작
  - 검사 중 HEAD/브랜치 변경 감지, 작업 트리·index 무변경 보장 동작
  - 채점 도중 사용자 저장소를 수정하지 않음(테스트로 확인)
  - GitHub Pages CORS 허용 확인 -> pages 채점 fetch는 정상
  - 코드 블록의 <찾은-SHA> 같은 자리표시자는 HTML로 사라지지 않고 표시됨
  - 배포본과 로컬 소스가 동일

상세한 수정 권고는 CODE-REVIEW-ISSUES.txt 를 참고하세요.
